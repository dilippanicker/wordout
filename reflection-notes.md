# Workflow Diagnosis — Wordout Development History

Diagnostic assessment of local setup and workflow friction, derived from git log (175 commits), CHANGELOG.md (26 versions, 2026-06-25 → 2026-07-05), CLAUDE.md, and `.claude/session-handoff.md` / TODO.md. No solutions were built — this is the ranked assessment only.

## Ranked Assessment

### 1. Release Pipeline Skill (bump → changelog → CI trigger → release link)
* **Action Type:** Skill / Automation
* **Leverage Score:** High — the ceremony fires on every release (26 releases in 11 days, ~2.4/day) and every step is mechanical, so build cost is very low relative to recurrence. The one human decision (semver choice) stays as a confirmation gate; everything around it can be scripted.
* **Evidence:** CLAUDE.md § Version Bumping Protocol (3-step manual protocol, "wait for confirmation") and § Build Pipeline ("trigger manually from Actions tab"). Git shows the process erring under load: three bumps in a single day (cce4405, 65b788c, 95a2208 on 2026-07-05), a rebuild-only bump (3e04274, "versionCode 23 rebuild"), and out-of-order version commits v1.2.9 before v1.2.8 (3f1f8d3 immediately after b124f5e).
* **Description:** Every build requires reading `app.json`, proposing a bump, editing `app.json` + `CHANGELOG.md`, committing, then leaving the terminal to click "Run workflow" in the GitHub Actions web UI. A single project skill (e.g. `/release`) can do the read-propose-confirm-edit-commit sequence and trigger the build from the CLI via `gh workflow run build-apk.yml`, then report the release download URL — eliminating the web-UI hop and the versionCode ordering/skip errors that manual coordination has already produced.

### 2. Pre-Release Device Smoke-Test Skill
* **Action Type:** Skill
* **Leverage Score:** High — bug-fix churn is the dominant cost in this history (19 of 26 versions contain fixes, ~73%), and much of it traces to changes shipped without on-device verification. A checklist-driven verification skill is cheap to build; even catching one regression per release cycle pays for it immediately.
* **Evidence:** "Post-test fix bundle" commits show bugs surfacing only after device testing: 0b93b64 ("fix: v1.2.2 post-test — B1 label position, B2 board refresh, B3 difficulty lock..."), bd0d52d, 1e79657, with CHANGELOG v1.2.8 referencing issues B1–B13. The Enter key shipped broken in v1.5.5 (glyph typed as a literal character instead of submitting — CHANGELOG v1.5.6, commits eda4ace/8f99c7a/0073190). TODO.md lists "[ ] Device regression test" as an unresolved follow-up for sessions 15, 17, 18, and 20.
* **Description:** Changes are verified on the web dev server (`npx expo start`) but repeatedly break on device or in end-to-end input flows, producing whole patch versions that exist only to fix the previous one. A pre-build smoke-test skill — a short, versioned checklist of the known-fragile paths (keyboard submit/backspace, mode switching, daily gate cycling, animation replay on revisit, dark theme) run on web plus a device pass before any version bump — turns the recurring "post-test fix bundle" into pre-release catches. It also directly addresses the perpetually deferred "device regression test" TODO.

### 3. Store-Invariant Unit Tests in CI
* **Action Type:** Automation
* **Leverage Score:** High — state-isolation bugs are the single largest bug category in the CHANGELOG, and Zustand stores are plain TypeScript testable with Jest alone (no device, no Reanimated, no CI changes beyond one job). Medium build cost, very high recurrence.
* **Evidence:** CHANGELOG chains: difficulty-lock logic wrong three times in three versions (v1.2.2 "Difficulty locked after any game completes (not just daily)", v1.2.3, v1.2.4); snapshot persistence bugs in v1.2.3/v1.2.4/v1.2.6; keyboard union-across-boards bug (v1.5.2); hard-mode constraints rejecting valid guesses across boards (v1.2.8); and the `boardCount > 1` default-of-4 bug that hid the Stats Daily tab for 9+ versions until v1.4.1. CLAUDE.md now carries a bolded rule ("**Never use `boardCount > 1` to detect multi-board mode**") purely to stop this recurring.
* **Description:** Mode-detection and state-isolation invariants currently live only as prose warnings in CLAUDE.md, enforced by hoping the next session reads them. A small Jest suite over `settingsStore`/`gameStore`/`quordleStore`/`dailyStore` asserting the documented invariants (mode detection via `gameMode`, per-board constraint independence, snapshot round-trips, per-difficulty daily answer derivation, `maxGuessesForDifficulty` as the single guess-count source) would convert the biggest bug category from device-discovered regressions into red CI before commit.

### 4. Session-Close Drift Guard
* **Action Type:** Skill (harden the existing /close) / Automation
* **Leverage Score:** Medium — recurrence is high (every session, 32 of 175 commits are session-close commits) and build cost is low, but the cost per incident is doc staleness rather than shipped bugs, so it ranks below the release/testing items.
* **Evidence:** TODO.md § Session 20 follow-up: handoff and TODO "lagged two versions (1.5.5, 1.5.6) behind CHANGELOG.md... no session-close ritual was run for those two version bumps." Explicit cleanup passes were needed: a072c5b ("docs: dedupe CLAUDE.md, fix stale facts ~336→302 lines"), 89ec1e9 ("fix: correct contradictory Play Store status"). Three session-close commits are no-change commits (f6d7824, c2e1b69, 5dda821); `docs/playstore.md` was created then deleted within 8 days (d590ec3 → b7ff83a) because it "consistently went stale" (session-handoff.md).
* **Description:** The /close ritual updates five docs by convention, and when a session skips it the docs silently diverge until a manual dedupe pass reconciles them. Add a cheap drift check to /close (and optionally /open): compare `app.json` version against the latest CHANGELOG.md heading, the CLAUDE.md "Current version" line, and the handoff's stated version, and flag mismatches instead of relying on memory. Skipping the no-change commit when nothing substantive changed would also stop diluting history.

### 5. Animation Lifecycle Regression Harness
* **Action Type:** Fix (targeted)
* **Leverage Score:** Medium — recurrence is high (the longest-running bug family, spanning v1.0.1 → v1.2.8) but build cost is also high: the fragility lives in Reanimated timing and React remount semantics, which resist cheap unit testing. Per the rubric, high recurrence + high build cost warrants a targeted fix, not broad automation.
* **Evidence:** CHANGELOG chain across six versions: v1.0.1 ("Win-row bounce was broken"), v1.0.4 (overlay delayed to let ✓/✗ settle), v1.2.2 ("Win/lose animations fire only once per game"), v1.2.5, v1.2.6 ("wave animation re-triggering on board revisit"), v1.2.8 ("`onWaveDone` now fires at true wave end"; fill no longer re-fires on mode switch). Same-day feature-then-revert: 5928520 → 3c2443c. CLAUDE.md's § Animation sequence is the densest guard-rail section in the file (stale-closure refs, `waveSentRef` double-fire guard, the `!waveDoneLocal` FlipTile gate, "Do NOT call onWaveDone at wave start") — documentation written specifically to stop re-breaking it.
* **Description:** The wave/fill/celebration sequencing is a de-facto state machine implemented as interacting refs, flags, and remount keys spread across `GameBoard` and three stores; each new mode or board count re-exposed an edge. The targeted fix is to extract the sequencing decisions (should-fill / should-wave / should-celebrate / is-revisit) into a pure, prop-driven function that can be exercised in plain Jest against the scenarios the CHANGELOG documents, leaving Reanimated to render outcomes rather than hold logic. This converts the guard-rail prose into executable regressions.

### 6. Local Build Environment / CI Wait Reduction
* **Action Type:** Fix (targeted)
* **Leverage Score:** Low-Medium — the ~45-minute CI build is paid on every release (26 so far), but the fix cost is high and uncertain (Java/Gradle environment repair, or CI cache tuning), and items 1–3 reduce the *number* of builds, which attacks the same cost more cheaply.
* **Evidence:** CLAUDE.md § Build Pipeline: "Do NOT use local EAS builds — Java/Gradle environment issues. GitHub Actions is the only supported build path" and "Build time: ~45 min; faster with warm Gradle cache." Rebuild-only commits (3e04274) and same-day multi-bump sequences (cce4405/65b788c/95a2208) mean some of those 45-minute waits bought no new functionality.
* **Description:** With local builds forbidden, every fix — including one-line regressions like the Enter key — costs a full CI round trip before it can be device-tested as a release artifact. Two targeted options, in order of cost: (a) verify the Gradle cache is actually warm across runs and split the APK/AAB jobs to parallelize the sequential ~45-min pipeline; (b) diagnose the local Java/Gradle environment once (a single JDK 17 + Android SDK alignment pass) to restore a local escape hatch for install-and-test iterations. Not urgent if items 1–3 land, since fewer regression releases means fewer builds.
