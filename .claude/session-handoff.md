## What this session did

Started as a documentation cleanup (extracting resolved-incident write-ups from CLAUDE.md into a new REGRESSION_TRAPS.md, fixing a staleness bug in the dailyStore docs along the way — CLAUDE.md dropped from 340 to 288 lines, back under its ~300-line soft budget), then pivoted into a live bug-fixing session driven by real user reports on the itch.io web embed, then closed with an actual v1.6.0 release, a Play Store upload, and the project's first-ever itch.io devlog.

**itch.io embed scroll/frame/notch fixes.** The itch.io embed was 700×1050 — well past the app's own 430×932 web-card cap — which forced the surrounding itch.io page to scroll before the keyboard was reachable on typical laptops, and made the dark-backdrop card framing look bad (confirmed live: iframe DOM measurement showed 1227px needed to reach the bottom vs. a ~711px window). itch.io has no responsive/auto-fit sizing for non-Unity HTML5 (confirmed on the Edit Game page — only "Manually set size" or "Auto-detect, Unity only"). Fixed by shrinking the itch.io embed to 430×820 (external itch.io project setting, not in git) so it always renders full-bleed, and adding a theme-matched 1px border in `app/_layout.tsx` so there's still a visible boundary against the surrounding page without needing an oversized container. Also added `viewport-fit=cover` to the itch-specific HTML export (`scripts/itchio-postprocess.py`) so `env(safe-area-inset-*)` can activate on notched phones — best-effort, not verifiable against a real device from this sandbox.

**itch.io fullscreen-button overlap, fixed twice.** Once the embed went full-bleed, our own 📊 stats icon and itch's overlaid fullscreen-toggle button both landed in the bottom-right corner. First attempt reserved footer padding while `document.fullscreenElement` was falsy, on the theory that itch's fullscreen state would cascade into our own document via the iframe's `allowfullscreen` permission — user reported live that it didn't work, the padding stayed even in itch's actual fullscreen. Replaced with a `useWindowDimensions()` check instead: only reserve the clearance while the viewport is still at or under the web-card cap, since that's the only state where the card is genuinely edge-to-edge and shares a corner with itch's button — real fullscreen expands the iframe past the cap, so the card reverts to its normal centered/backdropped look with margin on all sides. Verified locally by embedding the app in a throwaway iframe test harness and resizing it past the cap.

**Daily mode now auto-advances Easy → Hard → Extreme.** User asked: after finishing Easy, the header emoji "peek" animation played and then nothing happened — the player was stranded on the completed board and had to manually tap the header emoji or a "Play Now" button to progress. `dismissEndGame()` in `app/(tabs)/index.tsx` now calls `setActiveDailyDifficulty()` itself right after the peek animation finishes, which the existing `activeWordleMode`/`activeDailyDifficulty` effect already turns into a `startOrResumeDailyGame()` call. Removed the now-dead "Play Now" button (`BottomStrip.tsx`) since the state it targeted is no longer reachable in normal play. Verified live in the web dev server: solving Easy then Hard auto-advanced to Hard then Extreme with zero taps at any point. This is the one change from the whole session with no `Platform.OS` guard — it affects the native Android app too, which is why it drove the version bump.

## Gotchas

- **`releases/wordout-latest.{apk,aab}` are gitignored and easy to leave stale.** If `build-apk.yml` is ever triggered by hand (e.g. because the `/release` skill can't be invoked directly), remember to `gh release download v<X.Y.Z> --pattern "*.apk" --pattern "*.aab" --dir releases --clobber` afterward — the skill normally does this automatically, but a manual protocol walk-through skips it silently. A Play Console "duplicate versionCode" rejection right after a fresh build is the tell; check the local file's byte size against the GitHub release asset's size first.
- **itch.io has no responsive/auto-fit embed sizing for non-Unity HTML5 games** — the "Viewport dimensions" (Width/Height) on the Edit Game page are the only lever. Any future embed-sizing change should stay at or under the app's own 430×932 web-card cap (`constants/layout.ts`) to keep rendering full-bleed; going taller than 932 risks forcing the surrounding itch.io page to scroll, since itch adds its own page chrome above the iframe and typical laptop browser viewports aren't tall enough to absorb both.
- **`document.fullscreenElement` does not reliably fire inside itch.io's iframe** even though the iframe has `allowfullscreen` — confirmed live, not just theoretical. Any future itch-embed-aware logic should key off `useWindowDimensions()` relative to the web-card cap instead of trying to detect itch's fullscreen state directly.
